# 열린 프로젝트 인식과 전송 입력창 (0.1.6)

Work 채팅은 요청할 때 현재 선택된 프로젝트 폴더를 조회한다. 편집기 탭이 없어도 프로젝트 이름, 실제 상대 경로 목록, 열린 파일 상태를 작업 계획과 일반 답변에 전달한다. 채팅 상단에 연결된 프로젝트와 조회한 파일 수를 표시한다. 빈 프로젝트와 프로젝트 미선택 상태를 구분한다.

- 탐색: 파일 최대 400개, 항목 1,200개, 깊이 8단계. 한도 도달 시 일부 조회임을 표시한다. 루트 조회 실패는 오류로 처리하고, 읽지 못한 하위 폴더는 수를 기록한다.
- 답변 참고 자료: 프로젝트 요약 2,000자와 코드/README 발췌 최대 4개(각 2,000자). 열린 파일과 계획에서 선택한 파일을 우선한다. 상대 경로를 사용하고 절대 루트 경로는 전송하지 않는다.
- 메인 프로세스의 폴더 경계 검증을 유지한다. 환경·인증 파일, 숨김 경로, 차단된 링크를 제외하고, 발췌에서 알려진 비밀값 패턴을 검사한다.
- 폴더를 열기만 하면 전송하지 않는다. 사용자가 요청할 때 해당 요청의 참고 자료로 전달한다. 폴더를 전환하면 Work 대화와 컨텍스트도 새로 시작한다.

기존 파일을 선택한 코드 요청은 기존 승인 절차로 처리한다. 코드 요청이지만 수정할 기존 파일이 지정되지 않은 경우에는 프로젝트를 참고한 코드 답변을 제공한다. 새 파일을 디스크에 자동 생성하지는 않는다. 프로젝트가 열려 있는데 대상 파일이 없다는 이유로 프로젝트를 다시 열라고 안내하던 오류를 제거했다.

Chat과 Work는 전송 접수 즉시 입력창을 비운다. 실패해도 이전 문장을 자동 복원하지 않으므로, 사용자가 다음 문장을 입력하고 있어도 덮어쓰지 않는다. 실패한 요청은 명시적인 ‘실패한 요청 다시 입력’ 버튼으로 복원한다. 첨부 파일은 실패 시 보존한다. Work에서는 기술 오류를 AI 답변으로 추가하지 않으며, 실패한 사용자 요청은 다음 작업 계획의 대화 기록에서 제외한다.

검증은 `tests/unit/project-context.test.ts`, `tests/e2e/project-context.spec.ts`, 기존 `unified.spec.ts`와 `markdown-attachments.spec.ts`를 사용한다. E2E는 실제 Electron, 임시 중첩 프로젝트와 로컬 API 서버를 사용하며 외부 유료 AI 호출은 하지 않는다.

0.1.6 검증 결과: 타입 검사와 빌드 통과, 데스크톱 단위 테스트 70개 통과, 개발 실행 E2E 3개와 Windows 패키지 E2E 3개 통과. 최초 제한된 샌드박스에서 실행된 파일 접근 테스트는 `realpath` 권한 오류가 발생했으며, 승인된 실행 환경에서 전체 70개를 다시 실행해 통과했다. Windows 실행 파일의 제품 버전은 0.1.6이며, 로컬 실행기 `.tools/Start-Team-App.cmd`가 해당 버전을 실행한다. 기존 앱·서버 프로세스와 사용자 데이터는 유지했다.
