# 통합 프롬프트 채팅과 터미널 — 0.1.1

2026-10-30 사용자 요청에 따라 Work 챗봇의 챗·파일 검색·웹 검색·코딩 탭을 제거했다. 상단 모델 선택에는 서버가 제공하는 GPT-6.1 Sol과 Astra를 표시하며 기본값은 GPT-6.1 Sol이다. 작업 판단, 일반 답변, 검색 후 답변, 코드 제안에 선택한 모델을 그대로 사용한다. 오류 시 다른 모델로 바꾸지 않는다.

## 한 입력창의 처리 흐름

로컬 프로필 모드에서 프롬프트와 최근 대화, 접근 가능한 프로젝트 파일 이름을 인증된 로컬 API의 `/api/plan`으로 보낸다. Responses API의 JSON Schema 출력으로 일반 대화·프로젝트 검색·코드 설명/수정 중 필요한 처리를 판단한다. 키워드 정규식으로 제품의 작업 종류를 결정하지 않는다.

- 일반 대화는 스트리밍 답변을 제공한다. `web_search`와 `tool_choice: auto`를 사용해 모델이 필요할 때 웹을 검색하며 실제 반환된 출처만 표시한다.
- 프로젝트 검색은 허용된 현재 프로젝트에서 실제 검색한다. 최대 20개 검색 결과 구간을 AI에 전달해 답변하며 실제 파일 경로·줄 번호를 눌러 편집기로 열 수 있다.
- 코딩은 계획에 포함된 기존 파일만 읽어 서버로 전달한다. 수정은 같은 대화의 Diff에서 승인·거절한다. 기존 세션·프로젝트·파일 버전·승인 digest·만료 검사를 유지한다. 미저장 편집이 있으면 작업을 차단한다.
- 중단하면 서버 요청과 에이전트 요청을 취소하고 늦은 응답은 적용하지 않는다. 프로필 전환·프로젝트 전환은 대화와 제안을 분리한다.

파일 목록은 최대 400개, 탐색은 8단계·1200개 엔트리까지다. 숨김·비밀·링크 경로는 기존 검사를 사용한다. 계획의 파일 경로는 제공된 목록의 부분집합이어야 한다. 모델이 반환한 임의 명령은 실행하지 않는다. 현재 코드 제안은 기존 파일 수정에 한정하며 파일 생성·삭제·이름 변경과 AI의 자동 명령 실행은 제공하지 않는다. 사용자 PowerShell/Git Bash 터미널은 별도로 직접 사용할 수 있다.

기존 Oracle 서버 모드는 통합 입력창에서 일반 대화·자동 웹 검색·권한 있는 등록 문서 검색을 사용한다. 로컬 `/api/plan`과 코드 제안은 DB 없는 로컬 API 모드에 제공한다. 서버 API 키는 변경하거나 클라이언트로 전달하지 않았다.

## 터미널 표시와 입력

프로젝트를 열고 Work 터미널을 표시하면 PowerShell을 자동 시작한다. 연결 전·시작 중·실패·종료 상태를 빈 검은 화면 대신 표시하고 재연결 버튼을 제공한다. 터미널 영역을 클릭하면 xterm에 키보드 초점을 준다. 숨김·복원과 Chat/Work 전환 때 크기를 재측정하고 다시 그린다. 앱의 일반 textarea 스타일이 xterm의 숨겨진 입력창 크기에 영향을 주지 않도록 분리했다.

Windows 기본 ConPTY를 사용하며 별도 번들 OpenConsole DLL을 강제하지 않는다. 시작 응답보다 먼저 도착한 출력의 보관·재생은 유지한다. 터미널 권한 안내 문구는 오류가 아니며, 터미널에서 직접 입력한 명령은 현재 OS 사용자 권한으로 실행된다.

패널을 최소 높이로 줄여도 도구막대와 권한 안내가 실제 터미널 행을 밀어내지 않도록 제한했다. 자동 시작은 다른 입력창의 초점을 가져오지 않으며, 터미널 클릭이나 수동 시작으로 초점을 옮긴다.

## 이 PC 실행

`.tools/Start-Team-App.cmd`는 0.1.1 포터블 앱을 우선 실행한다. 실행 중인 기존 EXE를 덮어쓰지 않도록 결과물은 `apps/desktop/release/0.1.1`에 생성한다. 앱의 설정에서 버전 `0.1.1`을 확인할 수 있다.

새 통합 서버는 `.tools/local-ai-unified-server.json` 연결 파일과 운영체제가 정한 별도 루프백 포트를 사용한다. 기존 앱·서버를 종료하지 않으며 이전 메모리 대화는 이전 서버에 남는다. 새 서버로 대화 이력을 자동 복사하지 않는다. 새 서버의 메모리 대화도 서버 종료 시 사라지는 기존 제약은 유지한다. `Start-Team-App.ps1 -ServerOnly`는 창을 열지 않고 새 서버만 준비한다.

## 검증

- 타입 검사·서버/데스크톱 빌드·diff 검사 통과.
- 단위 테스트 113개: 서버 49개, 데스크톱 64개 통과.
- 개발 Electron E2E에서 단일 입력창의 요청별 자동 처리, 실제 프로젝트 검색, Sol/Astra 선택, 승인 전 파일 보존과 승인 후 적용, 프로필 격리를 모의 API로 확인했다. API 허용 목록과 버전 기대값을 0.1.1에 맞추고 해당 보안·설정 테스트를 다시 통과했다.
- 실제 PowerShell/Git Bash 실행·입력·Ctrl+C·리사이즈·재시작·자식 프로세스 정리, 어두운 테마와 작은 화면에서 마우스 클릭 후 입력, 패널 숨김·복원 및 Chat/Work 왕복 후 입력을 확인했다.
- 새 로컬 서버는 실제 Sol 모델 접근 조회에 성공했고 두 모델 목록을 반환했다. 실제 유료 Responses 요청이나 Astra 계정 접근 성공을 주장하지 않는다.

공식 구현 근거: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Web search](https://developers.openai.com/api/docs/guides/tools-web-search).

최종 배포 검증: 0.1.1 unpacked 앱에서 터미널·통합 채팅 E2E 2개 통과. 최종 포터블을 새 실제 서버에 연결해 PowerShell 영역 클릭 후 명령 입력·출력, Sol/Astra 모델 목록을 확인했다(CDP 연결, 격리된 임시 프로필). 포터블의 직접 Electron 자동화 연결 대신 실제 실행 후 CDP로 검증했다. 개발 E2E의 실행 파일 환경 변수용 2개 테스트는 기본 실행에서 건너뛰었으며, 최종 포터블과 unpacked 검증으로 별도 확인했다. Windows 설치 마법사 재설치는 하지 않았다.

## 0.1.2 — 연결 확인 결과 표시

Chat의 연결 확인과 Work의 연결 새로고침을 누르면 상단에 진행 상태를 표시한다. 완료 후 연결 정상/실패, 서버가 반환한 설명과 한국 시각 기준 확인 시간을 유지한다. 확인 중에는 버튼 문구를 바꾸고 중복 클릭을 막는다. 예외가 발생하면 이전 성공 상태를 그대로 사용하지 않고 연결 불가 상태로 갱신한다. 연결 확인은 서버와 기본 모델을 조회하며 유료 AI 답변은 생성하지 않는다.

검증: 데스크톱 타입 검사·빌드, 실제 Electron의 연결 실패 → 확인 중 → 성공 → 재실패·복구 흐름과 설정·테마 테스트 2개 통과. 기존 서버를 재시작하지 않는다. 실행기는 `release/0.1.2/win-unpacked/Local AI Workspace.exe`를 실행한다. 이번 UI 수정은 unpacked Windows 앱으로 제공하며 0.1.1 포터블·설치 파일은 다시 만들지 않았다.

## 0.1.3 — 마크다운과 대화 첨부

Chat과 Work 답변에 CommonMark/GFM 렌더러를 적용한다. 제목·굵게·기울임·목록·체크 목록·인용·표·링크·코드 블록을 해석하고, 코드 구문 강조와 복사 버튼을 제공한다. 수식은 `$…$`, `$$…$$`, GPT 답변의 `\(…\)` 및 `\[…\]`를 KaTeX로 표시한다. 원시 HTML은 실행하지 않으며 임의 원격 이미지는 자동 로드하지 않는다. 웹/문서 출처 버튼은 유지한다. ChatGPT 비공개 렌더러와의 픽셀 단위 일치를 의미하지 않는다.

두 입력창의 `파일·이미지 첨부` 버튼, 이미지 붙여넣기와 파일 드래그로 첨부한다. 전송 전 파일 이름·크기·이미지 썸네일을 표시하며 이미지 확대와 개별 삭제를 지원한다. 최대 4개, 파일당 10MB, 요청 합계 20MB다. PNG/JPEG/WEBP, PDF/DOCX/XLSX/PPTX, UTF-8 TXT/MD/CSV/TSV/JSON 및 지원 코드 파일을 받는다. 숨김·비밀 파일 이름, 허용 목록 밖 확장자, 위조 MIME·기본 파일 헤더, 손상된 base64와 초과 크기는 거부한다. 모든 형식의 전체 구조 유효성이나 악성 코드 검사를 보장하지 않는다.

파일 선택만으로 업로드하지 않는다. 사용자가 보내면 서버가 선택한 모델의 Responses API에 이미지 `input_image`, 문서 `input_file`, UTF-8 텍스트 `input_text`로 전달한다. 모델 오류 시 다른 모델로 대체하지 않는다. 첨부만 보내기도 가능하며 실패 시 입력과 첨부를 남겨 재시도한다. Work에서 첨부한 턴은 파일·이미지를 분석하는 일반 답변으로 처리하고 프로젝트 수정 계획은 이후 요청에서 판단한다.

완료된 사용자 메시지에 첨부를 보관해 다음 질문에 재전달한다. 로컬 서버는 프로필별 메모리 대화에 보관하고 삭제 시 함께 제거한다. 대화별 첨부 40MB, 서버 전체 256MB 한도를 둔다. 서버 종료 시 사라지는 기존 제약은 유지한다. 새 서버는 `.tools/local-ai-attachments-server.json`을 사용하며 이전 서버의 메모리 대화는 이전 서버에 남는다. 자동 이관하지 않는다.

Oracle 모드는 `005_chat_attachments.sql`의 `s3_attachments` 테이블에 같은 완료 트랜잭션으로 보관하며 대화 삭제 시 FK cascade로 제거한다. 서버 스키마 요구 버전은 5로 올렸다. Oracle 운영에 적용하려면 기존 백업·배포 절차에 따라 `pnpm --filter @local-ai-workspace/server db:migrate`가 필요하다. 이 작업에서 실제 Oracle DB 마이그레이션·통합 테스트는 실행하지 않았다. 현재 PC의 DB 없는 실행에는 필요 없다.

타입 검사·양쪽 빌드, 단위 테스트 117개(서버 53, 데스크톱 64), 개발 Electron E2E 5개를 통과했다. 모의 Responses 서버로 실제 첨부 내용·선택 모델·후속 컨텍스트와 프로필 격리, 큰 본문 수신을 확인했다. 실제 Electron에서 표·코드·수식·복사·이미지 확대·첨부 삭제·붙여넣기·드래그·실패 후 재시도와 기존 검색 출처·통합 작업·터미널을 검증했다. Oracle 저장/복원 및 스키마 4→5 경로는 모의 연결로 검증했다. 실제 유료 Responses 요청으로 첨부 모델 호환성을 확인한 것은 아니다.

실행기는 `release/0.1.3/win-unpacked/Local AI Workspace.exe`를 사용한다. 기존 앱의 작업을 저장하고 종료한 뒤 `.tools/Start-Team-App.cmd`로 다시 연다. 설정의 앱 버전에서 0.1.3을 확인한다. 이전 포터블·설치 파일은 변경하지 않았다.

공식 전송 형식 근거: [File inputs](https://developers.openai.com/api/docs/guides/file-inputs), [Images and vision](https://developers.openai.com/api/docs/guides/images-vision).

최종 0.1.3 Windows unpacked 실행 파일에서도 첨부·마크다운, 통합 작업·실제 터미널, 모델 선택·연결 결과·프로필 격리 E2E 3개를 통과했다. 새 실제 로컬 서버의 연결 상태와 첨부 스키마 수용도 확인했다. 이 확인은 모델 조회와 존재하지 않는 대화의 소유권 거부까지만 수행했으며 유료 Responses 호출은 0회다.
