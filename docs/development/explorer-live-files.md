# Explorer 파일 작업과 실시간 갱신 (0.1.7)

Explorer에 파일명 검색, 내용 검색, 생성·이름 변경·휴지통 이동과 Git 작업 메뉴를 추가했다. AI 서버에 연결하지 않아도 로컬 파일 작업과 검색을 사용할 수 있다.

| 조작 | 동작 |
| --- | --- |
| 상단 새 파일·새 폴더 | 선택한 폴더 안에 생성한다. 파일 선택 시 그 파일의 부모 폴더를 사용한다. |
| 폴더/파일 우클릭 또는 행의 `···` | 편집 열기, 생성, 이름 변경, 휴지통 이동, Git 검토, 상대 경로 복사, 새로고침 |
| 프로젝트 제목 우클릭 | 프로젝트 루트에 생성하거나 루트 아래의 변경을 Git 검토한다. |
| `Ctrl+P` | 경로·파일명 검색 입력창으로 이동한다. |
| `Ctrl+Shift+F` 또는 검색 활동 아이콘 | 로컬 파일 내용 검색 입력창으로 이동한다. |
| `F2` / `Delete` | 선택한 항목 이름 변경 / 휴지통 이동 확인창 |
| 방향키 좌·우 | 선택한 폴더 접기·펼치기 |

검색 결과를 누르면 부모 폴더를 펼치고 기존 Monaco 편집기로 연다. 파일명 검색은 파일 내용을 읽지 않고 경로의 부분 문자열로 찾는다(대소문자 무시). 최대 200개 결과, 10,000개 항목, 깊이 20, 3초로 제한한다. 내용 검색은 기존의 텍스트 검색 한도와 환경·인증 파일 제외 규칙을 유지한다. 검색어 입력 및 파일 변경을 지연 처리하고, 오래된 검색 결과가 새 검색을 덮어쓰지 않도록 순서를 검사한다.

Windows에서는 프로젝트 루트를 재귀 감시하므로 열지 않은 하위 폴더도 감지한다. `.git`, 빌드·의존성 폴더 및 임시 저장 파일은 알림에서 제외한다. 다른 플랫폼에서는 기존 폴더별 감시를 유지한다. 열린 트리는 포커스 복귀 시와 5초마다 다시 조회해 누락된 변경을 보완한다. 요청 순서와 프로젝트 ID를 검사하며, 삭제된 폴더의 하위 트리·펼침 상태를 정리한다.

깨끗한 열린 파일은 외부 수정 시 갱신하고, 미저장 내용은 보존하면서 디스크 충돌을 표시한다. 앱에서 파일이나 폴더의 이름을 바꾸면 그 아래 열린 탭 경로도 함께 갱신한다. 외부에서 삭제·이동된 파일은 편집 내용을 유지하고 읽을 수 없다는 상태를 표시한다.

생성은 독점 생성(`wx`/`mkdir`)으로 기존 항목을 덮어쓰지 않는다. 이름 변경은 대상 중복과 프로젝트 경계를 검사한다. 이름 변경·휴지통 이동 전에는 미저장 내용을 저장해야 한다. 경로의 모든 부모와 세션을 메인 프로세스에서 검증하며 프로젝트 루트, `.git`, 링크 및 하드 링크를 통한 잘못된 접근을 차단한다. 휴지통은 Electron `shell.trashItem`을 사용하며 실패 시 영구 삭제로 대체하지 않는다. 휴지통 이동은 확인창에서 실제 상대 경로를 보여준다. 파일 조작은 Git 인덱스를 자동 수정하지 않는다.

Explorer의 상태 표시는 현재 Git 상태와 연동한다. 파일 및 폴더 메뉴의 스테이징·해제는 기존 `GitPanel`의 검토·승인 흐름을 사용한다. 승인 전에는 인덱스를 변경하지 않으며, 기존 만료·상태 변경·인증·비밀정보 검사를 유지한다. 파일 내용은 스테이징 해제로 지우지 않는다. Git 작업은 한 번에 최대 100개 경로다. 상태 갱신 중 접수된 다음 Explorer 요청은 갱신 완료 후 처리하며, 프로젝트 ID를 확인해 이전 폴더의 요청을 넘기지 않는다. 준비 상태와 오류는 Explorer가 보이는 작업 화면에도 표시한다.

폴더 아이콘은 [Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme)의 기존 고정 커밋 `23e86c06d09e92571ef027184c00cad78e8c827f`에서 가져온 37종·253개 이름 매핑을 사용한다. `src`, `tests`, `docs`, `components`, `config`, `python`, `java` 등에 서로 다른 아이콘을 표시하고 펼침 상태에 따라 열린 이미지를 사용한다. 알려지지 않은 이름에는 기본 폴더 아이콘을 표시한다. 열린 변형은 같은 커밋의 공식 경로 치환 방식으로 생성했다. MIT 라이선스와 생성 스크립트를 보관한다.

검증: `tests/unit/workspace.test.ts`, `tests/unit/file-icons.test.ts`, `tests/e2e/explorer.spec.ts`, 기존 `workspace.spec.ts`, `workbench.spec.ts`, `git-workbench.spec.ts`, `indent-guides.spec.ts`. UI 테스트는 임시 프로젝트에서 실제 파일, Git 인덱스, Electron 편집기·메뉴·휴지통을 사용한다. 사용자 프로젝트나 원격 저장소를 수정하지 않는다.

최종 결과: 타입 검사·빌드 통과, 데스크톱 단위 테스트 전체 78개 통과. 개발 실행에서 Explorer·Git·워크벤치·편집기·IPC·수직선 관련 E2E 8개를 확인했다. 최종 Windows 0.1.7 패키지에서는 Explorer, Git 이력·브랜치, 수직선, AI 프로젝트 인식, 통합 채팅·터미널의 E2E 5개를 확인했다. 마지막 통합 테스트는 기능 검증 후 화면 캡처에서 한 번 시간 초과되어 단독 재실행했으며 캡처까지 통과했다. 초기 UI 검사에서 발견한 도구 모음 너비 및 Git 연속 요청 누락을 수정하고 재검증했다. 기존 편집기 테스트 선택자도 새 행 메뉴와 숨겨진 Git 패널을 구별하도록 수정했다.

로컬 실행기 `.tools/Start-Team-App.cmd`는 `release/0.1.7/win-unpacked/Local AI Workspace.exe`를 실행한다. 기존 앱과 서버 프로세스는 종료하지 않았으며, 사용자가 기존 앱에서 작업을 저장하고 종료한 뒤 실행기로 다시 열어 적용한다. 커밋·push는 수행하지 않았다.
