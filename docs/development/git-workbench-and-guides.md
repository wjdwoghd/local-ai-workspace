# Git 화면과 계층 가이드 — 0.1.5

## 소스 제어

긴 GitHub 안내와 전체 해시·브랜치 목록을 기본 패널에서 제거했다. 저장소·현재 브랜치·커밋 입력창, 스테이징된 변경 사항, 작업 파일 변경 사항, 병합 충돌을 구분한다. 파일 이름·폴더·상태 문자·개수와 개별/그룹 스테이징·해제 버튼을 표시한다. 파일을 클릭하면 중앙 Monaco Diff에 스테이징 ↔ 작업 파일 또는 HEAD ↔ 스테이징을 구분해 연다. 같은 파일의 인덱스와 작업 파일이 모두 변경된 경우 두 그룹에 각각 표시한다. 보호 파일은 스테이징하지 않으며 보호된 인덱스 항목의 해제는 기존 검사를 따른다.

커밋, 스테이징, 해제와 원격 작업은 기존 승인·상태 재검사·비밀 파일 검사·작업 기록을 유지한다. GitHub 연결 도움말, 연결 조회, Push/Pull/PR 입력은 별도 창에서 연다. 로컬 상태 조회는 GitHub API를 호출하지 않는다. 로컬 프로필은 개인 작업 기록을 저장하며, Oracle 서버 모드는 인증된 서버 기록을 사용한다. GitHub 작업에는 기존의 HTTPS origin·CLI 인증·이력 검사 제한이 적용된다.

`Ctrl+Shift+G`로 소스 제어를 연다. 브랜치 선택 창에서 로컬 브랜치를 검색·전환하거나 새 브랜치를 만들 수 있다. 미저장 편집 또는 저장소 변경이 있으면 전환/생성을 막으며 자동 stash를 하지 않는다. 승인 이후 HEAD·인덱스·파일·설정·브랜치 ref가 달라지면 실행하지 않는다. 브랜치 이름의 옵션 주입과 기존 브랜치의 경로 이름 충돌도 거부한다.

## 하단 상태와 이력

파란 상태 표시줄에 현재 브랜치와 변경 표시 `*`, 추적 브랜치의 받을/보낼 커밋 수, 현재 HEAD의 짧은 해시와 커밋 제목을 표시한다. 추적 브랜치가 없으면 `원격` 버튼으로 표시한다. 브랜치를 누르면 선택 창, 최근 커밋을 누르면 이력 창, 송수신 상태를 누르면 원격 작업 창을 연다. 소스 제어 패널과 같은 상태를 공유하며, 파일 이벤트·화면 복귀·포커스와 5초 간격 조회로 외부 Git 변경을 반영한다. 개수는 로컬 추적 ref 기준이며 원격 검토 전까지 자동 fetch하지 않는다.

최근 최대 60개의 실제 커밋과 부모 ID로 그래프를 그린다. 커밋 제목·작성자·시각·해시·브랜치/태그를 검색할 수 있다. 커밋을 선택하면 변경 파일을 보여주고, 파일을 누르면 부모 커밋과 선택 커밋의 읽기 전용 Diff를 연다. 병합 커밋은 첫 부모와 비교한다. 비밀 파일·바이너리·허용 크기 밖 내용은 미리보기하지 않는다.

VS Code의 주요 Git 작업 흐름에 맞춘 화면이며 VS Code Git 확장의 모든 기능을 제공하는 것은 아니다. 현재 브랜치 선택은 로컬 브랜치에 한정한다. stash·cherry-pick·rebase·브랜치 삭제·강제 push·변경 폐기 기능은 추가하지 않았다. 기존 실제 Git hook을 실행하며 실패를 우회하지 않는다.

## Explorer와 코드 가이드

펼친 폴더의 자식 목록마다 1px 세로 계층선을 표시한다. 선택 파일의 상위 경로와 마우스가 위치한 목록은 더 밝게 표시한다. 폴더를 접으면 해당 하위 선도 함께 사라진다. 라이트/다크 테마에 각각 선 색상을 지정했다.

Monaco 편집기와 Diff 양쪽에 들여쓰기·괄호 쌍 수직선을 켜고 활성 블록을 강조한다. 여섯 단계 가이드 색상을 명시해 깊은 중첩에서도 표시한다. 코드 내용이나 실제 들여쓰기를 자동 변경하지 않는다. Java 토크나이저와 확장자 매핑도 등록해 Java 키워드·문자열·숫자를 구분한다. 기존 D2Coding 글꼴과 터미널 색상은 유지한다.

## 실행

Windows unpacked 앱을 `apps/desktop/release/0.1.5/win-unpacked`에 만든다. `.tools/Start-Team-App.cmd`로 다시 실행하고 설정의 버전 `0.1.5`를 확인한다. 기존 로컬 AI 서버를 재시작하지 않으며 현재 서버의 대화 메모리도 그대로 사용한다. 서버 모드에 새 브랜치 작업을 배포할 때는 확장된 `recordGit` 작업을 포함한 서버 빌드도 반영해야 한다. DB 스키마 추가 변경은 없다.

설계 참고: [VS Code Source Control](https://code.visualstudio.com/docs/sourcecontrol/overview), [Source Control History](https://code.visualstudio.com/docs/sourcecontrol/history). Monaco 옵션과 테마 키는 설치된 0.57.0의 타입 정의·가이드 렌더러에서 확인했다.

## 검증 결과 — 2026-10-31

- 서버·데스크톱 타입 검사와 빌드 통과.
- 단위 테스트 120개 통과: 서버 53개, 데스크톱 67개. 최초 빌드 병렬 실행에서 기존 문서 파서 테스트 2개가 5초 제한에 걸려, 빌드 완료 후 전체 테스트를 순차 실행해 통과했다. 검사나 hook을 우회하지 않았다.
- 개발 Electron E2E 6개 통과: Git 소스 제어와 실제 브랜치 생성·전환·외부 변경 반영, 기존 서버 인증 모드, 폴더·Java·Diff 가이드, D2Coding과 PowerShell 색상, 통합 작업·작은 터미널 입력, 설정·보안.
- Windows 125% 배율에서 1px 경계가 계산상 0.8 CSS px로 표시되는 것을 확인해 시각 테스트가 이 배율을 고려하도록 했다. 폴더 네 단계의 실제 선 위치·색·두께와 접기/펼치기, 활성 코드 블록, 밝은/어두운 테마를 확인했다.

Git 검증은 격리된 임시 저장소를 사용했다. 실제 사용자 저장소에서 커밋·브랜치 전환·push·PR 생성은 수행하지 않았다.

최종 0.1.5 Windows unpacked 실행 파일에서도 Git 소스 제어·브랜치·상태 표시줄, Explorer/Java/Diff 수직 가이드, 통합 작업·실제 PowerShell 입력 E2E 3개를 통과했다. 실행기 경로도 0.1.5로 갱신했다. 설치 마법사 재설치와 실제 GitHub 원격 쓰기는 수행하지 않았다.
