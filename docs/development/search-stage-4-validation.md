# 4단계 검증 결과

검증일: 2026-10-30 (Asia/Seoul). Windows x64, 저장소 로컬 Node.js 24.22.2, pnpm 10.34.5.

구현 및 로컬 자동 검증을 완료했습니다. 실제 Oracle, 실제 Astra 웹 검색, 팀원 10명의 실사용 검증은 남아 있습니다. 4단계 완료 기준이 실제 운영 환경에서 충족되었다고 보장하지 않습니다.

| 검증 | 결과 |
| --- | --- |
| `pnpm typecheck` / `pnpm build` | 서버·Electron·공유 타입·테스트 타입 검사 및 빌드 통과 |
| `pnpm test` | 서버 28개, 데스크톱 9개, 총 37개 통과 |
| Electron E2E | 인증·채팅·테마/보안·검색 시나리오 총 4개 통과. 기존 패키지/포터블 2개는 EXE 환경변수 미지정으로 skip |
| `pnpm test:oracle` | TEST_ORACLE_* 설정 부재로 전용 스키마 통합 시나리오 1개 skip |
| Git | 기존 브랜치 및 사용자의 `AGENTS.md` 변경 유지. 커밋·push 없음 |
| 키 보호 | 기존 `.env`의 API 키 공란·Git 제외 확인, desktop 소스·빌드에 서버 API 키 설정 참조 없음 |

문서 단위 테스트는 실제 작업 스레드와 PDF.js, fflate, fast-xml-parser를 사용합니다. UTF-8 한글, PDF 페이지 텍스트, DOCX 문단·XML 엔티티·공백, PPTX 숫자 순서, XLSX 시트 관계·공유/인라인 문자열·저장된 값과 출처 위치를 확인합니다. 잘못된 형식·빈 텍스트·손상 PDF·확장자/경로 조작·XML 엔티티 선언·압축 크기 제한 위반도 확인합니다.

서버 테스트 대역은 인증/팀 권한 확인 이전 파싱 금지, 저장 전 팀 권한 재검사, SQL 바인드 검색과 접근 필터, 웹 검색 도구 옵션과 URL 인용 추출, 허용된 문서 구간만 Responses 입력에 포함, 출처 저장, 스트리밍 도중 문서 권한 상실 시 후속 응답 전달·완료 저장 금지, HTTP 무캐시 응답을 확인합니다. 기존 키 공란 상태의 실제 API 호출 차단 테스트도 통과했습니다.

Electron E2E는 Oracle/OpenAI 대신 명시적인 로컬 HTTP fixture를 사용합니다. 네이티브 파일 선택창은 테스트 파일 경로를 반환하도록 대체하고, 실제 Electron main에서 파일을 읽고 업로드합니다. 등록·검색·원문 구간 열기, 채팅의 문서/웹 인용, 외부 브라우저 열기 호출, 출처 저장·재로그인 복원, 다른 계정의 목록 분리, 문서 삭제를 확인합니다. 외부 브라우저 자체는 실행하지 않습니다. 기존 보안 테스트에 새 IPC 허용 목록과 위험한 출처 URL·잘못된 팀 ID 거부를 추가했습니다.

처음 샌드박스에서 실행한 E2E는 Electron 시작 시간 초과로 중단했습니다. 창 실행이 가능한 환경에서는 검색·인증·채팅 시나리오가 통과했습니다. 기존 보안 테스트의 IPC 목록에 새 메서드가 없어 실패한 항목을 갱신하고 재실행하여 테마·보안 시나리오도 통과했습니다. 화면 캡처와 테스트 산출물은 `apps/desktop/test-results`에 있으며 Git에서 제외합니다.

실제 Oracle 통합 시나리오에는 10명의 개인 문서 검색/조회/삭제 격리, 관리자도 타인의 개인 문서 접근 거부, 팀 공유와 비구성원 차단, 등록자 팀 제외 후 접근·삭제·검색 차단, 문서 삭제 시 구간 cascade, 출처 CLOB 저장·복원을 추가했습니다. 실제 DB가 없어 SQL 실행 및 마이그레이션 002→003·재실행의 성공 여부는 미검증입니다.

남은 검증: 실제 Astra 모델·계정의 웹 검색 및 인용 정확도, 실제 PDF/Office 업무 자료의 추출·검색 관련성, HTTPS 환경의 10MB 업로드와 SSE, 다중 서버에서의 권한 변경 경쟁, 대량 문서 성능, 10명 동시 실사용. Windows 설치 프로그램은 이번 단계에서 재생성하지 않았습니다. 설정과 사용법은 [4단계 안내](search-stage-4.md)를 참고하세요.
