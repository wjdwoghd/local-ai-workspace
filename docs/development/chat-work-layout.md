# Chat / Work 화면 구성

> 0.1.1의 현재 동작과 실행 파일은 [통합 채팅·터미널 안내](unified-chat.md)를 참고하세요. 아래 내용은 이전 화면 구성 기록을 포함합니다.

앱의 주 메뉴를 **Chat**과 **Work** 두 개로 통합했다. 로컬 프로필과 기존 서버 로그인 모두 동일한 화면 구조를 사용한다. 프로필 선택 또는 로그인 후 기본 화면은 Chat이다.

## Chat

- 대화·검색 응답을 읽는 화면과 입력창을 중심으로 배치한다. 왼쪽에는 새 대화와 대화 기록만 남기고 큰 로고와 기능별 메뉴를 제거했다.
- 대화 사이드바는 기본 196 CSS px, 작은 창에서는 166 px이며 상단 버튼 또는 `Ctrl+B`로 숨길 수 있다. 접힌 상태에서도 상단 `＋`로 새 대화를 만들 수 있다.
- 웹 검색은 입력창의 옵션으로 사용한다. 기존 서버의 파일 첨부·문서 관리도 입력창 및 도구 메뉴에서 연다.
- 설정·문서 관리·팀 자료/사용량은 주 메뉴로 분리하지 않고 상단 **도구** 메뉴의 대화상자로 연다. 키보드 초점은 대화상자 안에서 이동하며 Esc 또는 닫기 버튼으로 복귀한다. 서버가 지원하지 않는 문서·협업 기능은 로컬 모드에 새로 노출하지 않는다.
- 로컬 모드에서는 API 연결 전에도 새 초안을 만들 수 있다. API가 실제 준비된 후 첫 전송 시 서버 대화를 생성한다. 초안을 서버 대화 ID로 교체할 때 스트림을 지우거나 빈 이력으로 덮어쓰지 않는다.

## Work

Work에서는 앱의 대화 사이드바를 숨기며 창 전체 너비를 작업 공간에 사용한다. VS Code와 같은 영역 관계를 유지한다.

```text
┌──────────────────── Chat / Work ───────────────────────┐
│ 프로젝트 도구 모음                                      │
├────┬──────────┬─────────────────────┬───────────────────┤
│활동│ 탐색기 / │ 파일 탭·코드 편집기  │ 보조 챗·AI 도구   │
│표시│ 소스 제어│                     │                   │
│줄  │ / 설정  ├─────────────────────┤                   │
│    │         │ PowerShell / Git Bash│                  │
├────┴──────────┴─────────────────────┴───────────────────┤
│ 상태 표시줄                                             │
└─────────────────────────────────────────────────────────┘
```

기존 사이드바·챗 너비와 터미널 높이 드래그 조절, 파일 확장자별 Material 아이콘, 실제 셸, Git 검토·승인, API 코딩 Diff 승인은 유지한다. 작업 공간을 숨길 때 편집기·파일 감시·PTY를 종료하지 않는다. Work의 `Ctrl+B`는 탐색기, `Ctrl+백틱`은 하단 터미널을 토글하며 Chat에 있을 때 숨겨진 Work의 단축키를 실행하지 않는다.

## 전환과 분리

### 창 크기 변경과 연결 안내 보완

Chat의 `.composer-wrap`에 남아 있던 850px 최대 너비와 화면 기준 여백 계산이 겹치면 최대화 시 입력창이 오히려 좁아졌다. 최대 너비 제한을 제거하고 대화 내용과 입력창에 같은 비례 여백을 적용했다. Work 챗은 고정 픽셀 대신 작업 영역 너비의 비율(초기 28%, 최소 240px·최대 40%)로 관리하며 드래그한 비율을 창 크기 변경 시 유지한다.

Chat과 Work의 입력 영역에 AI 전송 불가 상태와 연결 재확인 버튼을 표시한다. 초안을 유지한 채 서버가 실제 사용 가능 상태를 반환하면 전송을 활성화한다. 파일 검색은 AI가 연결되지 않아도 계속 사용할 수 있다. 실제 계정은 키 인증 200, `gpt-6-astra` 모델 조회 404로 재확인했으며 모델 변경·권한 검증 우회는 하지 않았다. [공식 오류 안내](https://developers.openai.com/api/docs/guides/error-codes)를 확인했다. 이 UI 수정은 실행기가 사용하는 포터블 앱에 반영하며 이전 Setup 파일의 갱신 여부와 구분한다.

임시 API E2E에서 모델 404일 때 전송 차단·초안 보존, 접근 복구 후 재확인 시 활성화, 창 최대화 시 입력창 폭 증가, 전체화면에서 Work 챗의 28% 비율을 검증한다. 실제 계정의 Astra 생성 성공을 뜻하지 않는다.

이 보완의 타입 검사·데스크톱 빌드·전체 UI 13개가 통과했다. 최종 패키지에서 연결 복구 및 사용자 조절 비율 보존 E2E 1개와 Windows 실행·단일 포터블 실행 2개도 통과했다. 포터블 EXE를 갱신했고 Setup EXE는 이번 보완에서 다시 만들지 않았다. 실제 서버를 재시작하거나 실제 사용자 프로필·대화를 변경하지 않았다.

Chat ↔ Work 전환은 프로젝트를 닫거나 프로필을 바꾸는 동작이 아니다. Chat 초안·대화와 Work의 열린 파일·미저장 수정·패널 크기·터미널을 유지한다. 프로필 변경·로그아웃·프로젝트 전환 시 기존 미저장 확인 및 세션 폐기 규칙은 그대로 적용한다. Work 챗이 프로젝트 변경으로 초기화될 때 관련 없는 Chat 응답을 중단하지 않도록 해당 챗이 직접 시작한 요청만 취소한다.

로컬 사용자 이름·테마·프로필 전환은 공통 상단 바에 작게 배치하고 Git 작업 기록은 설정 안으로 옮겼다. 기존 서버의 관리자 계정 관리는 관리자에게만 계속 제공한다. API 키나 인증 경로는 변경하지 않았다. 실제 계정의 Astra 접근 권한 대기 상태도 유지하며 [API 연결 안내](local-api-connection.md)를 따른다.

## 검증

E2E는 주 메뉴가 Chat/Work 두 개인지, 기본 Chat과 접을 수 있는 사이드바, Work의 전체 창 너비 사용, 모드 간 Chat 초안·API 대화·미저장 코드 보존, 기존 API 코딩 승인·프로필 간 접근 차단을 확인한다. 기존 대화 저장·검색 출처·테마·인증·Git·ConPTY 회귀도 새 메뉴와 도구 대화상자 경로로 검증한다. 자동 테스트의 API 응답은 mock이며 실제 Astra 모델 접근 성공으로 보고하지 않는다.

포터블 검증 중 채팅 IPC 완료 결과가 마지막 검색 출처 이벤트보다 먼저 처리되어 이벤트 구독이 일찍 해제되는 현상을 확인했다. 같은 이벤트 채널의 완료 표식을 받은 뒤 구독을 해제하도록 수정했다. 마지막 응답의 출처 보존과 웹 검색 요청 옵션을 E2E에서 함께 확인한다.

최종 소스 빌드와 타입 검사가 통과했으며 전체 UI 회귀는 13개 통과, 실행 파일 환경 변수가 필요한 2개는 별도 패키지 검증으로 분리했다. 로컬 API·검색 출처·승인·모드 전환 시나리오 반복 3회도 통과했다.

단위 테스트는 데스크톱 64개·서버 45개, 총 109개가 통과했다. 기본 샌드박스에서 사용자 Temp 경로의 `realpath` 접근이 거부된 첫 실행은 실패했으며, `TEMP`/`TMP`를 작업 공간 내 `.tools/stage6-temp`로 지정하고 파일·ConPTY 접근을 허용해 다시 검증했다.

초기 Windows 패키징과 화면 캡처는 디스크 공간 부족(ENOSPC)으로 실패했다. 내용과 경로를 확인한 이전 Electron/NSIS 임시 캐시 및 실패한 패키지 임시 폴더만 정리해 약 4GB를 확보한 뒤 재실행했다. 소스·실제 팀원 작업 공간·프로필·API 키 파일은 정리 대상에 포함하지 않았다.

NSIS/포터블 동시 생성 시 임시 `elevate.exe` 복사가 실패해 두 타깃을 순서대로 다시 생성했으며 최종 빌드는 모두 성공했다. 최종 Windows 패키지의 API·출처·전환 검증 3회와 프로필·Work·단일 EXE 실행 검증도 통과했다. `app.asar`의 main·preload·renderer가 최종 빌드와 일치하며 환경 파일·실제 명단·페어링 설정이 포함되지 않음을 확인했다. 설치 마법사를 통한 실제 OS 설치·제거는 수행하지 않았다.

이 환경에서는 기존 `.tools/Start-Team-App.cmd`를 실행하면 로컬 서버와 새 포터블 UI를 함께 연다. 배포 결과는 `apps/desktop/release/Local-AI-Workspace-0.1.0-Setup.exe`와 `Local-AI-Workspace-0.1.0-Portable.exe`이다. 실행 파일에 서버 키나 로컬 연결 설정을 포함하지 않으므로 다른 PC에서는 별도의 서버 연결 설정이 필요하다. 실제 서버 연결은 확인했지만 Astra 모델 접근 권한은 대기 중이며 실제 AI 생성 성공으로 간주하지 않는다.
