# 4단계 웹·파일 검색

Electron에서 선택한 로컬 문서를 서버에 등록하고, 개인·팀 문서 검색 결과를 Astra 채팅에 활용합니다. 웹 검색은 Responses API의 `web_search` 도구를 사용합니다. 기본 표시명은 Astra이며 기존 서버 모델 설정과 계정 접근 검사를 유지합니다. 설정이 없는 경우 모델을 바꾸거나 데모 검색 결과를 만들지 않습니다.

## 준비와 실행

Node.js 24, pnpm, Oracle 19c 이상(AL32UTF8), 2단계 인증 환경이 필요합니다. 기존 서버를 중지하고 아래 명령을 저장소 루트에서 실행합니다.

```powershell
pnpm install --frozen-lockfile
pnpm --filter @local-ai-workspace/server db:migrate
pnpm dev:server
# 별도 터미널
pnpm dev
```

마이그레이션은 `001_auth.sql` → `002_chat.sql` → `003_search.sql` 순서로 적용하며 이미 적용한 버전을 건너뜁니다. 현재 서버는 `s2_control.version = 3`을 요구합니다. Oracle DDL은 자동 커밋되므로 운영 DB 변경 전 백업이 필요합니다. 003은 팀, 구성원, 문서 메타데이터, 추출 구간, 메시지별 출처 테이블을 추가합니다. 기존 대화 데이터는 유지됩니다.

서버 전용 환경 변수는 기존 [3단계 안내](chat-stage-3.md)를 따릅니다. 새 필수 환경 변수는 없습니다. `apps/server/.env`는 Git 제외 상태로 유지하며 API 키를 데스크톱으로 전달하지 않습니다. 키가 없어도 인증된 문서 등록·단어 검색·원문 확인은 작동하지만 AI 채팅 및 웹 검색은 실행하지 않습니다.

## 사용 방법

1. 로그인 후 **웹·파일 검색** 메뉴에서 개인 문서 또는 소속 팀을 선택합니다.
2. **로컬 파일 선택·등록**을 누릅니다. 선택 파일의 추출 텍스트와 이름이 서버에 저장되며, 팀 범위로 등록하면 해당 팀 구성원이 검색할 수 있습니다.
3. 검색어로 등록 문서를 검색합니다. 결과 출처를 누르면 해당 구간을 표시하고, 전체 추출문도 확인할 수 있습니다.
4. 채팅에서 **개인·팀 문서 검색**, **웹 검색**을 필요에 따라 선택하고 질문합니다. 문서 검색을 선택하면 관련 구간 최대 6개와 대화 내용이 AI 제공업체로 전송됩니다. 웹 검색을 함께 선택하면 문서 기반 내용이 웹 검색 질문에 영향을 줄 수 있습니다. 민감한 문서는 회사의 외부 전송 정책을 확인하세요.
5. 답변의 `[D1]` 표시는 문서 위치를, 웹 인용 표시는 외부 브라우저의 출처 페이지를 엽니다. 완료된 답변과 출처는 함께 저장됩니다. 데모에서는 검색 도구를 사용하지 않습니다.

관리자는 같은 화면에서 팀을 만들고 계정을 구성원으로 추가·제외할 수 있습니다. 팀을 만든 관리자는 첫 구성원이 됩니다. 등록자는 현재 접근할 수 있는 자신의 문서를 삭제할 수 있습니다. 잘못 등록한 문서는 삭제 후 다시 등록합니다. 이 단계의 로컬 검색은 사용자가 선택해 등록한 파일의 검색이며, 폴더 마운트·자동 변경 감지는 5단계 범위입니다.

## 파일 처리와 제한

| 형식 | 추출 범위와 위치 |
| --- | --- |
| PDF | 텍스트 레이어, 페이지 번호. 이미지 OCR 미지원 |
| DOCX | 본문·본문 표 안의 문단, 문단 번호 |
| XLSX | 워크북에 연결된 시트, 셀 참조·공유 문자열·인라인 문자열·저장된 값, 시트 이름·행 번호 |
| PPTX | 슬라이드 텍스트, 슬라이드 번호 |
| TXT, MD | UTF-8 텍스트, 줄 번호 |

파일당 10MB, 추출문 100만 UTF-16 코드 단위, 최대 1,000구간, PDF 300페이지, 사용자당 100개 문서로 제한합니다. 구간은 최대 1,200코드 단위이며 긴 본문은 200코드 단위가 겹치도록 나눕니다. ZIP은 최대 3,000항목, 항목당 압축 해제 크기 10MB, 전체 30MB로 제한합니다. 파싱은 서버 프로세스당 최대 2개 작업 스레드에서 실행하며 각 작업에 128MB V8 힙 제한과 20초 기한을 둡니다. 이 제한은 전체 프로세스 메모리 상한이나 OS 격리를 의미하지 않습니다. 파서 진단과 업로드 본문은 로그로 남기지 않습니다.

암호화·손상 파일, 검색 가능한 텍스트가 없는 파일은 오류로 안내합니다. Office 매크로·수식·외부 링크는 실행하지 않습니다. DOCX 머리글·바닥글, PPTX 발표자 노트, 이미지·차트 내부 텍스트는 추출하지 않습니다. XLSX 수식은 계산하지 않고 저장된 셀 값을 읽습니다. 레이아웃·표의 시각적 재현은 제공하지 않습니다.

검색은 Oracle의 바인드 변수와 대소문자 무시 부분 문자열 일치로 점수를 계산합니다. 질문에서 최대 8개 단어를 추출하여 일치 단어 수가 높은 6개 구간을 사용합니다. 의미·벡터 검색이나 한국어 형태소 분석은 제공하지 않으며, 대량 자료의 검색 성능과 관련성은 별도 검증이 필요합니다. 검색 화면에서 실제 키워드를 확인하고 질문하면 결과를 개선할 수 있습니다.

## 권한과 보관

개인 문서는 본인만 접근합니다. 관리자가 타인의 개인 문서를 읽는 예외는 없습니다. 팀 문서는 등록자·관리자를 포함해 **현재 팀 구성원**만 목록·검색·원문 조회가 가능합니다. 팀 범위는 서버 세션과 DB 구성원 정보로 결정하며 클라이언트가 소유자를 지정할 수 없습니다. 팀 관리 작업은 관리자 역할을 요구합니다.

문서 등록 전·저장 전 권한을 검사합니다. 채팅은 검색 구간을 공급하기 전, 응답 조각 전달 및 저장 전에 문서 접근을 재검사하고, 권한이 사라지면 완료 저장을 중단합니다. 이미 제공업체에 전달한 내용이나 사용자에게 전달된 내용을 회수하지는 않습니다. 문서 삭제·팀 제외 후에도 이전에 완료된 개인 대화의 답변과 출처 이름은 기록으로 남습니다. 출처 원문을 다시 열 때는 현재 권한을 검사합니다. 원본 파일 바이너리와 로컬 절대 경로는 서버에 보관하지 않습니다.

Electron은 신뢰한 메인 프레임 IPC에서만 파일 선택과 출처 열기를 허용합니다. 렌더러가 임의 로컬 경로를 읽도록 요청하는 인터페이스는 없습니다. 외부 출처는 인증정보 없는 HTTP(S) URL만 허용하며 `file:`, `javascript:`, 프로그램 실행 프로토콜은 거부합니다. 네트워크 업로드는 인증된 서버로만 전송하고 리다이렉트는 거부합니다.

## API와 공식 자료

- `POST /api/documents`: Bearer 인증, 파일 이름·base64·선택 팀 ID. 최대 10MB JSON 업로드.
- `POST /api/action`: `documents`, `teams`, `searchDocuments`, `readDocument`, `deleteDocument`; 관리자 전용 `createTeam`, `addTeamMember`, `removeTeamMember`.
- `POST /api/chat`: 기존 필드에 선택적인 `webSearch`, `documentSearch` 불리언을 추가합니다. SSE의 `sources` 이벤트는 현재 출처 목록을 전달하고 기존 `delta`, `done`, `error`를 유지합니다.

구현은 [OpenAI Docs의 웹 검색 안내](https://developers.openai.com/api/docs/guides/tools-web-search)를 확인했습니다(2026-10-30). Responses에 웹 검색 도구를 지정하고, 반환된 URL 인용의 제목·주소·문자 위치를 저장하여 클릭 가능한 인용을 표시합니다. 공식 문서 예시는 `gpt-6-astra`를 사용하지만 이 계정의 실제 도구 접근 권한과 유료 실행은 아직 검증하지 않았습니다. 지원하지 않는 모델에서 검색 요청이 실패하면 오류로 처리하며 다른 모델로 대체하지 않습니다.
