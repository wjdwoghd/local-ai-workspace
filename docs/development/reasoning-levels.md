# 모델별 추론 수준 (0.1.8)

Chat과 Work에 Light, Medium, High, Extra High, Max, Ultra 선택을 제공한다. GPT-6.1 Sol을 기본 모델로 유지하며 Astra에도 같은 선택을 제공한다. 기본 추론 수준은 Medium이다. 이 기기의 프로필 ID와 실제 모델 ID별로 선택을 보관해 모델·화면·프로필 전환 및 재실행 시 복원한다. 데모와 추론 지원 설정이 없는 모델에서는 선택을 비활성화한다.

| 화면 표시 | 실제 처리 |
| --- | --- |
| Light | Responses `reasoning.effort: low` |
| Medium | `medium` |
| High | `high` |
| Extra High | `xhigh` |
| Max | `max` |
| Ultra | 서버의 독립 검토 3개를 병렬 실행하고 최종 종합 1개 실행. 각각 `max` 사용 |

선택은 일반 채팅, 작업 판단(`/api/plan`), 코드 제안(`/api/code`)에 전달한다. 프로젝트를 여는 동안에는 이전 프로젝트 화면에서 모델·수준을 변경하거나 새 요청을 보내지 못하게 해 화면 교체 중 선택 초기화가 생기지 않도록 했다. 진행 중인 요청의 선택을 잠그며 다음 요청부터 변경을 반영한다.

Ultra는 이 앱에서 구현한 병렬 검토·종합 모드다. Codex의 내부 실행기를 사용하는 것은 아니며, API에 지원되지 않는 `reasoning.effort: ultra`를 보내지 않는다. 검토자마다 접근법, 정확성·보안 대안, 검증·경계 사례를 검토한다. 검토자에게 로컬 파일 쓰기나 명령 실행 권한을 주지 않고, 웹 도구도 검토 요청에서는 제외한다. 검토 결과는 신뢰하지 않는 참고 자료로 최종 요청에 넣고 원래 사용자 요청과 출력 스키마를 유지한다. 중간 결과와 숨겨진 사고 과정은 채팅 답변으로 노출하지 않는다. 최종 코드 제안에도 기존 파일 범위·버전·승인 검사를 적용한다.

한 Ultra 실행은 검토 3회와 종합 1회이므로 일반 실행보다 많은 사용량이 발생한다. Work에서 판단과 최종 작업을 모두 수행하면 각각 이 구조를 사용한다. 화면에도 여러 번 요청하므로 시간과 사용량이 늘어난다고 표시한다. 병렬 요청의 사용량과 최종 사용량을 합산해 한 번 보고한다. 중단 신호는 모든 검토 요청으로 전파하며, 검토 하나가 실패하면 다른 검토도 취소하고 종합하지 않는다. 다른 수준이나 모델로 자동 대체하지 않는다.

출력 토큰 한도는 Light 8,192, Medium 16,384, High 32,768, Extra High·Max 65,536이며 Ultra 검토자는 각각 32,768, 종합은 65,536이다. 이는 내부 추론 토큰도 소모하는 한도다. 기존 화면 출력·파일 크기 한도와 별개로 적용한다. 서버 시간 한도는 일반 120초, Extra High·Max 300초, Ultra 600초이며 데스크톱도 이를 고려한다. 실제 완료 시간이나 답변 품질 향상을 보장하는 값은 아니다.

서버 `chatModels`는 확인된 기본 모델의 수준을 메타데이터에 제공한다. 별도 API 모델 ID는 자동으로 추론 지원을 가정하지 않는다. 운영자가 공식 문서와 계정 지원을 확인하고 `OPENAI_ADDITIONAL_MODELS`의 모델 항목에 `reasoningEfforts`를 명시할 수 있다. 지원하지 않는 값, 중복 값 및 Max 없이 Ultra만 선언한 설정은 거부한다. API 키는 서버 `.env`에서만 사용하며 이번 작업에서 값을 변경하지 않았다.

이번 서버 전환에는 로컬 대화 보존을 추가했다. `.tools/local-ai-reasoning-history`에 프로필별 완료 대화를 저장하고 Windows ACL을 현재 OS 사용자·SYSTEM·Administrators로 제한한다. 서버 재시작 시 소유자·메시지·첨부 형식을 검증하고 복원한다. 저장은 임시 파일 교체로 수행하며 저장 실패 시 해당 변경을 되돌리고 완료 이벤트를 보내지 않는다. 대화 변경은 프로필별로 직렬 처리한다. 저장 파일·연결 정보·로그는 Git에서 제외한다.

`apps/server/scripts/migrate-local-history.cjs`는 기존 로컬 API의 인증된 대화 조회를 이용해 최초 한 번 보존한다. 기존 저장 파일을 덮어쓰거나 원본 서버를 종료하지 않는다. 대화 내용과 인증값은 출력하지 않는다. 새 실행기는 별도 `.tools/local-ai-reasoning-server.json` 연결을 사용한다. 이전 앱을 종료하고 새 실행기로 열어 새 서버를 사용한다. 이전 앱에서 전환 후 계속 진행한 대화는 자동 동기화되지 않으므로 이전 서버는 복구 가능한 상태로 유지했다. Oracle 스키마 변경은 없다.

검증은 서버 `reasoning.test.ts`, `local-history.test.ts`, `models.test.ts`와 기존 채팅·첨부 테스트, 데스크톱 `reasoning.spec.ts`와 기존 통합 채팅·Explorer·첨부 E2E로 수행한다. 병렬성, 취소 전파, 합산 사용량, API 파라미터, 승인 전 파일 보존, 프로필별 복원, 서버 재시작 후 대화 격리를 확인한다. 생성 테스트는 모의 OpenAI 전송을 사용하며 실제 계정에서는 모델 조회와 서버 설정·보관 대화 복원만 확인한다.

최종 검증 결과: 서버 타입 검사·빌드 및 단위 테스트 62개, 데스크톱 타입 검사·빌드 및 단위 테스트 78개 통과. 개발 Electron의 신규 추론 선택·기존 통합 채팅·프로젝트 인식 검사를 확인했고, 최종 Windows 0.1.8 패키지 E2E 4개(Explorer, 마크다운·첨부, 추론 선택·프로필 복원, 통합 채팅·터미널)가 통과했다. 실제 새 로컬 서버의 기본 모델 접근 확인과 두 모델의 6단계 설정 정보, 보관 대화 복원도 확인했다. 로컬 실행기는 0.1.8을 가리킨다. 원본 서버와 앱은 종료하지 않았고, 이전 연결을 사용하는 실행 스크립트도 `.tools/Start-Team-App-0.1.7.ps1`로 보관했다. 커밋·push는 수행하지 않았다.
