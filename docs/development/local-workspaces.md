# DB 없는 로컬 팀원 작업 공간

후속 변경으로 선택 가능한 [DB 없는 로컬 API 서버](local-api-connection.md)를 연결했다. 이 PC 실행기는 현재 Oracle 없이 API 서버와 앱을 시작한다. 아래의 완전 오프라인 동작은 연결 파일을 지정하지 않은 모드의 설명이다. 개인 프로필 분리는 동일하게 유지한다.

사용자 요청에 따라 이 PC의 로컬 실행을 서버 로그인에서 로컬 프로필 선택으로 전환했다. Oracle·SQLite·IndexedDB 같은 DB를 사용하지 않으며, 서버 요청 없이 개인 폴더와 JSON 설정 파일을 사용한다. 비밀번호 계정 인증과 구분되는 작업 공간 선택 기능이다.

## 실행

기본 앱은 `AUTH_SERVER_URL`이 없으면 로컬 모드로 시작한다. 이 PC의 Git 제외 실행기 `.tools/Start-Team-App.cmd`는 `LOCAL_WORKSPACE_MODE=1`로 로컬 모드를 강제하고, 이전 서버 URL을 제거한다. 서버·TLS 프록시·Oracle을 시작하지 않고 포터블 앱만 실행한다. `.tools/Start-Team-App.ps1`도 같은 방식이다.

`LOCAL_WORKSPACE_ROSTER_FILE`은 선택 사항인 로컬 명단 JSON 파일의 절대 경로다. 최초 프로필 목록이 없을 때만 이름 배열을 가져온다. 실제 명단은 Git이나 설치 파일에 포함하지 않는다. 이 PC 실행기는 기존의 Git 제외 명단 파일을 이용한다. 다른 PC의 새 설치에서는 화면에서 이름을 입력하여 개인 작업 공간을 만들 수 있다.

```powershell
$env:LOCAL_WORKSPACE_MODE = '1'
Remove-Item Env:AUTH_SERVER_URL -ErrorAction SilentlyContinue
pnpm dev
```

기존 서버 연동 코드는 보존했다. 명시적인 `AUTH_SERVER_URL`이 있고 로컬 강제 모드가 아닌 경우에만 서버 모드를 사용한다. 패키징 앱의 서버 모드 HTTPS 검사는 유지한다. 로컬 모드에서 서버 전용 API를 호출하면 비활성 결과를 반환하며 네트워크로 우회하지 않는다.

## 프로필별 분리

| 항목 | 저장 위치/동작 |
| --- | --- |
| 명단 | Electron `userData/local-workspaces/profiles.json`, 무작위 UUID와 표시 이름만 저장 |
| 기본 작업 폴더 | `local-workspaces/<프로필 UUID>/project` |
| 개인 테마·프로젝트 연결·최근 Git 기록 | `local-workspaces/<프로필 UUID>/state.json` |
| 편집기·터미널·승인 | 프로필 전환 시 기존 workspace ID와 승인 폐기, watcher 및 PTY 정리 |
| 다른 프로젝트 연결 | 폴더 선택·기존 경로 검사 후 소유 프로필에 기록. 다른 프로필이 연결한 폴더와 그 상위/하위 폴더 접근 차단 |

이름을 선택하고 작업 공간을 연 뒤 **내 작업 폴더 열기**를 누르면 개인 기본 폴더를 연다. 기존 프로젝트도 선택할 수 있지만 같은 경로를 여러 프로필에 중복 연결할 수 없다. 팀원이 같은 저장소를 쓰려면 개인별 checkout/복사본을 선택한다. 선택한 폴더와 연결 상태는 개인별로 보존되며 재실행해도 유지한다. 파일 탐색기·Monaco·직접 터미널·Git/GitHub 및 로컬 승인 흐름은 기존 구현을 사용한다.

프로필 전환 전에 저장하지 않은 편집을 저장·폐기·취소할 수 있다. 저장 충돌이나 실패 시 전환을 중단한다. 이전 프로필의 workspace ID, 세션 generation으로 시작한 늦은 요청은 거부한다. 개인 기록 API는 현재 프로필 파일만 읽고 다른 프로필의 상태 경로를 renderer에서 지정할 수 없다. JSON 저장은 임시 파일과 rename을 사용하고, 손상 파일은 덮어쓰지 않는다. 링크 디렉터리·특수 경로는 기존 검사와 프로필 저장소 검사로 거부한다.

서버가 필요한 AI 채팅·문서 업로드/팀 공유·관리자·API 사용량 화면은 로컬 화면에서 제공하지 않는다. 사용량·비용을 만들어 표시하지 않는다. 실제 코딩 AI는 기존처럼 미연결이며 로컬 파일 검사와 승인 기반 기능만 남는다. API 키를 클라이언트에 추가하지 않는다.

## 분리의 한계

이는 같은 Windows 계정 안에서 선택하는 로컬 프로필이다. 별도 로그인 인증·OS ACL sandbox가 아니다. 같은 OS 계정의 파일 탐색기나 직접 터미널은 다른 폴더에 접근할 수 있다. OS 차원의 접근 통제까지 필요하면 팀원별 Windows 계정과 파일 권한을 사용해야 한다. GitHub CLI 자격 증명도 Windows 계정 단위이며 프로필별 GitHub 인증을 새로 제공하지 않는다. 프로필 선택 화면에 명단 이름은 표시된다.

## Oracle 및 기존 구성

이 앱용 Node 인증 서버와 TLS 프록시만 경로/포트/명령을 확인하여 종료했다. `LOCALAI_TEAM` PDB는 닫고 저장된 자동 열기 상태를 해제했다. 계정과 DB 파일은 삭제하지 않았다. 기존 `FREEPDB1`은 READ WRITE 상태로 유지했고 Oracle 서비스는 종료하지 않았다. 새 로컬 앱은 `.env`나 Oracle 드라이버를 읽지 않는다. 이전 DB 자격 증명은 Git 제외 서버 설정과 운영자 파일에 보존되지만 로컬 앱에서 사용하지 않는다.

기존 서버/Oracle 검증 결과는 과거 서버 모드 결과이며 로컬 프로필의 인증 보증으로 해석하지 않는다. 현재 검증 결과는 [로컬 작업 공간 검증 기록](local-workspaces-validation.md)에 정리한다.
