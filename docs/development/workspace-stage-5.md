# 5단계 — 로컬 프로젝트와 개발 환경

Windows의 **로컬 개발 환경 → 프로젝트 열기**에서 네이티브 폴더 선택창으로 프로젝트를 엽니다. OS 드라이브를 마운트하지 않습니다. 파일·터미널 출력은 서버나 AI로 자동 업로드되지 않으며, 기존 검색 문서 등록은 별도의 명시적인 작업입니다. Astra 표시명과 서버 모델 설정은 변경하지 않았습니다.

## 실행과 패키징

기존 [인증 서버 안내](auth-stage-2.md)에 따라 Oracle 스키마 3과 서버를 준비합니다. 로컬 파일 작업에도 로그인이 필요하지만 OpenAI 키는 필요하지 않습니다. 서버 키는 서버의 로컬 `.env`에서만 관리합니다.

```powershell
pnpm install
pnpm dev:server
# 다른 터미널
pnpm dev

pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
pnpm package:win
```

현재 검증 플랫폼은 Windows 11 x64, Node 24.22.2, pnpm 10.34.5, Electron 42.11.18입니다. Node가 PATH에 없다면 저장소에 준비된 `.tools/node-v24.22.2-win-x64`와 `.tools/node_modules/.bin`을 현재 셸 PATH에 추가하고 PowerShell 실행 정책에 따라 `pnpm.cmd`를 사용합니다. 기존 pnpm 저장소와 다른 경로라는 오류가 나면 기존 `node_modules/.modules.yaml`의 `storeDir`에 맞춰 `--store-dir`를 사용합니다. 이 환경의 설치에는 `C:\Users\EZ\AppData\Local\pnpm\store`를 사용했습니다.

Monaco 0.57.0의 실제 exports 구조에 맞춰 `editor/editor.api.js`, 언어 등록과 feature 등록을 가져옵니다. [공식 ESM/Vite 안내](https://github.com/microsoft/monaco-editor/blob/main/docs/integrate-esm.md)의 worker 패턴을 사용하며 기본 편집·diff worker와 JSON worker를 로컬 번들로 제공합니다. CDN은 사용하지 않습니다. `worker-src 'self' blob:`과 로컬 글꼴만 CSP에 추가했습니다. JSON 스키마의 네트워크 요청은 기본 비활성이고, 제품 renderer의 네트워크 연결도 기존 production CSP에서 차단됩니다. TS/JS 등은 구문 색상을 제공하며 프로젝트 전체 TypeScript 언어 서버·자동 빌드·패키지 설치는 제공하지 않습니다.

터미널은 [node-pty](https://github.com/microsoft/node-pty) 1.1.0의 Windows x64 Node-API prebuild와 제공된 ConPTY DLL을 사용합니다. 설치 스크립트를 허용하지 않아도 이 플랫폼의 prebuild가 포함되어 있습니다. V8 ABI 기반 모듈과 달리 이 Windows 바인딩은 Node-API를 사용합니다. `npmRebuild: false`로 불필요한 소스 재빌드를 피하고 `asarUnpack`으로 node-pty 전체(네이티브 모듈·DLL·worker)를 풉니다. 플랫폼·Electron·node-pty를 바꿀 때는 [Electron 네이티브 모듈 안내](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)를 확인하고 실제 Electron/패키지 E2E를 다시 실행해야 합니다. Windows 외 플랫폼의 native build/패키징은 검증하지 않았습니다.

## 사용법과 단축키

- 프로젝트 이름·경로를 상단에서 확인합니다. **프로젝트 전환**, **프로젝트 닫기**를 지원합니다. 최근 프로젝트·열린 탭·파일 내용은 디스크에 저장하거나 자동 복원하지 않습니다.
- 탐색기에서 폴더를 펼칠 때 해당 디렉터리 하나만 읽습니다. 파일을 클릭하면 탭으로 열립니다. 선택 파일은 탐색기와 탭에서 표시됩니다. **새로고침**은 펼친 폴더만 다시 읽습니다.
- **Ctrl+S** 또는 **저장**으로 현재 파일을 저장합니다. 탭 닫기·프로젝트 전환·프로젝트 닫기·로그아웃·일반 창 닫기는 수정 파일마다 **저장 / 폐기 / 취소**를 묻습니다. 저장 실패·충돌이면 이동을 중단하고 편집 내용을 유지합니다.
- **저장본 비교**의 왼쪽은 마지막으로 읽거나 저장한 원본, 오른쪽은 현재 편집 내용입니다. Git diff가 아닙니다.
- 외부 변경이 있으면 수정하지 않은 파일은 갱신하고, 수정 중인 파일은 유지하며 충돌을 표시합니다. **디스크 비교**는 왼쪽에 마지막 감지한 디스크 버전을 표시합니다. **다시 읽기**는 수정 내용 처리 후 최신 파일을 읽습니다. 비교 화면에서 **명시적 덮어쓰기**를 누르면 비교된 디스크 버전을 다시 검사한 뒤 저장합니다. 그사이 디스크가 다시 바뀌면 다시 충돌 처리합니다. 삭제되었거나 읽을 수 없는 파일은 자동 재생성·덮어쓰기하지 않습니다. 편집 내용을 복사해 보관할 수 있습니다.
- **터미널 시작·재시작**은 현재 프로젝트 경로에서 Windows PowerShell을 `-NoLogo -NoProfile`로 엽니다. 실행 중 표시 후 입력합니다. Enter로 명령 실행, **Ctrl+C**로 중단, `exit`로 셸 종료, **터미널 종료**로 강제 정리합니다. 아래 패널의 모서리를 끌어 높이를 바꾸거나 창 크기를 변경하면 PTY 크기도 갱신합니다.
- Monaco의 기본 찾기·선택·복사·붙여넣기·실행 취소를 제공합니다. 라이트·다크·시스템 테마는 기존 앱 설정을 따릅니다. 탭 전환 때 편집 내용은 유지하지만 편집기 인스턴스를 다시 만들므로 undo 기록·커서·스크롤 위치는 유지하지 않습니다.

## 텍스트와 자원 제한

| 항목 | 정책 |
| --- | --- |
| 파일 | UTF-8, 파일당 최대 2 MiB. 잘못된 UTF-8·UTF-16 및 NUL/바이너리 제어문자를 차단 |
| 인코딩 보존 | UTF-8 BOM 유무 보존. LF·CRLF·CR 보존 |
| 혼합 줄바꿈 | Monaco 편집 offset을 원문 offset으로 변환해 편집 밖 구간의 줄바꿈 보존. 새로 삽입한 줄바꿈은 원본의 첫 줄바꿈 사용. 전체 붙여넣기로 교체한 구간은 새 삽입으로 취급 |
| 열린 탭 | 20개. 현재 로그인 세션의 메모리에만 보관 |
| 디렉터리 | 한 폴더당 5,000개 표시 항목. 초과하면 더 작은 폴더 선택 안내. 무제한 정렬·재귀 전체 스캔 없음 |
| 감시 | 열어 본 디렉터리 최대 128개, 디렉터리당 watcher 하나, 150ms 이벤트 합치기. 접은 폴더 감시는 프로젝트 종료까지 유지. 한도 도달 시 프로젝트를 다시 열 수 있음 |
| 루트 상태 | 2초마다 존재·접근·링크 상태 확인. 연결 상실 시 watcher·PTY 정리, 편집 내용은 유지 |
| 터미널 | 프로젝트당 하나. 입력 IPC 최대 8,192자, 크기 2~500열·2~200행, 출력 이벤트 최대 65,536자, scrollback 3,000행. 디스크 출력 로그 없음 |

기본 숨김·감시 제외 이름은 대소문자 구분 없이 `.git`, `node_modules`, `dist`, `build`, `release`, `.next`, `coverage`, `.pnpm-store`, `.tools`입니다. 내부 저장 임시 파일 `.local-ai-save-*`도 숨깁니다. 제외 폴더로 내려가지 않으며 파일 IPC로도 접근을 차단합니다. 나머지 숨김 파일은 표시될 수 있습니다. watcher는 펼쳐 보거나 열어 본 디렉터리에만 설치하며 재귀 감시는 하지 않습니다. OS 감시 이벤트는 정확히 한 번 전달을 보장하지 않고 이름 변경은 부모 목록을 다시 읽어 반영합니다. 이벤트 누락 시 새로고침할 수 있으며 저장 전 버전 검사는 별도로 수행합니다.

## 파일 IPC와 경로 보안

파일·PTY는 main에서 실행하고 renderer에는 Node/fs/임의 명령 실행 API를 노출하지 않습니다. preload는 `workspace`의 필요한 메서드와 구독 해제 함수만 제공합니다. main은 모든 작업공간 IPC의 호출 webContents·mainFrame·정확한 renderer URL·인자 개수·인자 구조·길이·세션 세대·활성 작업공간 ID와 터미널 ID를 검사합니다. 선택 경로는 네이티브 선택창에서만 받습니다. 파일 요청에는 main이 발급한 UUID와 `/` 구분 상대 경로만 사용합니다.

절대 경로, `..`, 빈 경로 구성요소, 역슬래시, 드라이브/UNC/장치 경로, ADS의 `:`, Windows 예약 장치명·후행 점/공백·제어문자·숨김 제외 경로를 거부합니다. 선택 루트와 조상, 요청 경로의 각 구성요소를 `lstat`/`realpath`로 검사합니다. 심볼릭 링크·junction 및 canonical 경로가 바뀌는 재분석 경로를 차단하며 루트 내부 링크도 허용하지 않습니다. 하드 링크 파일도 링크 수가 1을 넘으면 읽기·저장을 차단합니다. Windows의 모든 vendor-specific reparse tag를 직접 조회하는 네이티브 검사는 구현하지 않았습니다. Node가 링크로 인식하지 않으면서 canonical 경로도 그대로인 특수 재분석 지점에 대한 완전한 차단을 주장하지 않습니다.

파일 읽기·저장·폴더 열기·터미널 시작 등은 서버 `me`로 세션을 재검증합니다. 빈번한 터미널 키 입력·크기 변경·dirty 상태 IPC는 main이 보유한 인증 세션으로 검사하며, 열린 작업공간의 인증을 5초 주기로 서버에 확인합니다. 인증 확인은 기존 요청 큐·서버 응답 시간을 따르므로 원격 세션 폐기를 즉시 감지하는 보장은 없습니다. 인증 상실·확인 실패·로그아웃·새 로그인·renderer navigation/crash·창 종료에는 main 자원을 정리하고 reset 이벤트를 발행합니다. renderer는 ID가 다른 이전 응답·이벤트를 폐기하고 계정 전환 때 파일·탭·출력을 비웁니다. 인증 만료 때는 다음 사용자 노출 방지를 위해 저장 대화상자 없이 메모리 편집 내용을 폐기합니다. 서버 연결 확인에 실패한 경우에도 작업공간을 닫는 보수적 정책입니다.

## 저장 방식과 보장 한계

읽은 바이트의 SHA-256과 파일 identity·mtime·ctime·mode로 버전을 만듭니다. 저장은 현재 버전과 비교하고, 같은 디렉터리에 무작위 이름의 `wx` 임시 파일을 생성해 전체 바이트를 기록하고 `fsync`·close한 다음, 대상 경로와 버전을 다시 확인한 후 rename으로 교체합니다. 앱 내부 저장은 직렬화합니다. rename 실패 시 기존 파일을 먼저 삭제하는 fallback은 사용하지 않고 임시 파일 정리를 시도합니다. 읽기 전용 속성·권한 실패·삭제·지원하지 않는 내용이면 메모리 편집 내용을 유지합니다.

이 방식은 일반적인 외부 편집 충돌과 부분 쓰기 위험을 줄이며, **다른 OS 프로세스와의 원자적 compare-and-swap 또는 파일시스템 샌드박스는 아닙니다**. 마지막 검사와 open/rename 사이에 외부 프로세스가 파일·조상·junction을 교체하는 TOCTOU 경쟁은 남습니다. 디렉터리 핸들 기준 상대 접근·Windows 전용 no-reparse open/ReplaceFile API·배타 잠금은 구현하지 않았습니다. 같은 OS 계정의 적대적 프로세스가 계속 경로를 바꾸는 환경에는 강한 경계로 사용할 수 없습니다.

rename 원자성·내구성은 파일시스템에 의존합니다. 디렉터리 fsync·전원 장애 복구·네트워크 드라이브/분리형 매체의 내구성은 보장하지 않습니다. UNC와 링크 경로는 미지원이며 로컬 드라이브 문자로 연결한 네트워크 매체도 운영 검증하지 않았습니다. 기존 파일의 기본 mode는 반영하지만 명시적 Windows ACL·소유자·생성 시각·ADS·기타 파일 메타데이터를 그대로 복원하지 않습니다. 명시적 ACL 보존이 필수인 파일에는 사용하지 마세요. 프로세스 강제 종료 시 임시 파일이 남을 수 있으며 자동 정리·편집 복구·자동 저장은 없습니다.

## 터미널 보안과 범위

터미널은 **OS 사용자 권한으로 프로젝트 밖에도 접근**하고 파일을 삭제하거나 네트워크에 접속할 수 있습니다. 파일 IPC 경로 제한을 터미널 샌드박스로 설명하지 않습니다. 사용자가 입력한 명령만 전달하며 AI 명령 생성·자동 실행·코드 승인·Git/GitHub 작업은 구현하지 않습니다.

main 환경변수를 통째로 상속하지 않고 OS 경로·사용자 프로필·임시 디렉터리 등 명시된 허용 목록만 전달합니다. 서버 키·앱 인증 토큰·서버 설정·NODE_OPTIONS 등은 주입하지 않습니다. PowerShell 프로필도 자동 실행하지 않습니다. 그러나 같은 OS 사용자의 파일, 사용자별 도구 설정·자격 증명 및 사용자가 실행한 프로그램 자체의 접근은 차단하지 않습니다. ANSI 출력은 xterm으로 표시하며 자동 링크 열기·클립보드 addon은 사용하지 않습니다.

전환·로그아웃·종료 때 watcher와 구독, 터미널을 정리합니다. Windows는 자신이 시작한 셸 PID에만 `taskkill /T /F`를 호출하고 ConPTY를 닫아 일반 자식 프로세스도 정리합니다. 별도 서비스·스케줄러·분리된 프로세스로 이동한 작업이나 앱 강제 종료 후의 모든 외부 프로세스까지 정리한다고 보장하지 않습니다. 정상 셸 종료는 exit code를 표시하며 재시작할 수 있습니다.

실행 검증과 운영 미검증 항목은 [5단계 검증 기록](workspace-stage-5-validation.md)을 참고하세요.
